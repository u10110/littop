# Littop — плейбук smoke/regression для pre-prod

Стенд: `https://pre-prod.littop.ru/`

## Критический путь автора

1. Открыть `/` — главная страница отвечает `200`, отдаются HTML и hashed JS-бандл.
2. Открыть `/authors` — каталог авторов загружается, карточки и ссылки на страницы авторов видны.
3. Открыть публичную страницу автора `/author/<login>` — отображаются профиль, произведения и доступные внешние ссылки.
4. Войти тестовым автором — сессия устанавливается, открывается личный кабинет.
5. Открыть форму новой публикации — доступны раздел, жанр, заголовок, анонс и новый редактор.
6. Создать публикацию — произведение появляется в кабинете/ленте автора и открывается на странице произведения.
7. Открыть редактирование публикации — сохранённый текст и форматирование загружаются без потери данных.

## Чек-лист запуска

- [ ] `GET /` → `200`, HTML содержит текущий `index-*.js`.
- [ ] `POST /api` health/introspection → API отвечает без `5xx`.
- [ ] `/authors` → список авторов отображается.
- [ ] Публичная страница автора → `websiteUrl` и `profileLinks` отображаются только если данные есть.
- [ ] Публичная страница автора без внешних ссылок → блок ссылок отсутствует, страница не падает.
- [ ] Личный кабинет гостя → приватные действия требуют входа.
- [ ] Авторизованный кабинет → форма публикации открывается.
- [ ] После отправки публикации → успешный ответ GraphQL и новая публикация видна.

## Новый редактор произведения — обязательные состояния

Проверять на создании и на редактировании существующей публикации.

### 1. Пустое состояние

- Открыть форму без текста.
- Ожидание: редактор отображает placeholder, кнопка публикации/сохранения не ломает страницу; обязательная ошибка показывается валидацией.

### 2. Базовое форматирование

Ввести текст и применить по очереди:

- жирный;
- курсив;
- подчёркивание;
- заголовок/обычный абзац;
- маркированный и нумерованный список;
- цитату;
- ссылку.

Ожидание: форматирование видно в редакторе, сохраняется после отправки, перезагрузки и повторного открытия редактирования.

### 3. Переносы строк и смешанный текст

- Ввести несколько абзацев, пустую строку и длинный текст.
- Проверить `Enter` и `Shift+Enter` согласно подсказке редактора.
- Ожидание: абзацы не сливаются, HTML/JSON не показывается пользователю, текст не обрезается.

### 4. Очистка/повторное редактирование

- Сохранить форматированный текст.
- Открыть редактирование, удалить часть текста и изменить форматирование.
- Сохранить повторно.
- Ожидание: удалённый текст не возвращается, новое форматирование сохраняется.

### 5. Разделы и жанры

- Выбрать `Поэзия`, `Проза`, `Творческий проект`.
- Для каждого раздела проверить список жанров и пустой вариант «Не выбирать жанр».
- Ожидание: жанры относятся к выбранному разделу; при смене раздела старый жанр сбрасывается.

### 6. Ошибки и права доступа

- Гость открывает форму/мутацию → действие требует авторизации.
- Автор отправляет пустой обязательный текст → понятная ошибка, публикация не создаётся.
- Автор редактирует свою публикацию → сохранение разрешено.
- Другой пользователь пытается редактировать чужую публикацию → отказ, данные не изменяются.

## Проверки ссылок автора

- Заполненный `websiteUrl` → кнопка «Сайт автора» ведёт на правильный URL.
- Заполненный `profileLinks` → каждая кнопка имеет правильную подпись и URL.
- Нет `websiteUrl` и `profileLinks` → блок кнопок не отображается.
- Сохранение профиля без переданного `profileLinks` → существующие дополнительные ссылки не очищаются.

## Доказательства и критерий готовности

- Проверить HTML/hashed bundle через `curl`.
- Проверить GraphQL ответы через `curl`.
- Для SPA-рантайма предпочтительно пройти шаги в браузере и снять console errors; если браузер недоступен, явно отметить проверку как API/static, а не browser-runtime.
- Релиз считается проверенным только если критический путь пройден полностью и все затронутые состояния выше проверены.
