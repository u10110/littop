## Критические расхождения

1. **Staging отстаёт от текущего состояния рабочей frontend-ветки.**
   - На стенде подключаются `/assets/index-DE_Gu4sW.js` и `/assets/index-B5bmXhiA.css`; HTML изменён в 13:21:36 UTC.
   - Текущий checkout `new-design-pre-prod` имеет commit `f325796` от 16:48:31 +0300 и локальная production-сборка создаёт иные хэши: `index-CDRiiVwx.js`, `index-D1s6m3LZ.css`.
   - Следствие: проверять соответствие именно текущей ветке по pre-prod нельзя: стенд отстаёт от исходников.

2. **Старые `.html`-адреса макета не совместимы с картой маршрутов SPA.**
   - Макет использует `books.html`, `book.html`, `login.html`, `account.html` и другие HTML-страницы.
   - Приложение использует `/works`, `/works/:slugOrId`, `/personal` и т. п.; алиасы реализованы только для части адресов без расширения (`/books`, `/account`), но не для `books.html` и т. д.
   - На pre-prod `books.html` и другие такие адреса отдают общий 460-байтный SPA-shell с HTTP 200, а не нужный экран/redirect. Старые ссылки и закладки будут ломаться незаметно.

3. **Любой неизвестный URL маскируется под успешную страницу приложения.**
   - `/does-not-exist` отвечает HTTP 200 и отдаёт тот же SPA HTML, как `/works`, `/authors` и т. д.
   - В router нет маршрута catch-all/404. В результате битые ссылки не получают понятную страницу «не найдено».

## Расхождения с картой интерфейсов макета

### Реализованы маршруты или их эквиваленты

- Главная: `/`.
- Произведения: `/works` (макет: `books.html`).
- Страница произведения: `/works/:slugOrId` (макет: `book.html`).
- Авторы и страница автора: `/authors`, `/authors/:login`.
- Форум и тема: `/forum`, `/forum/:slugOrId`.
- Конкурсы, радио, кабинет: `/contests`, `/radio`, `/personal`.
- Вложенные страницы макета: рубрики, витрина, разделы форума, продвижение, редакция, журнал/активность, отзывы, альбомы, блоги, о проекте, контакты.

### Неполное или другое поведение

1. **Поиск в шапке — декоративный.**
   В `App.vue` это `<input>` без v-model, обработчика ввода/Enter, запроса или перехода на результаты. В макете он заявлен как «Поиск по сайту». Результатов поиска и маршрута для них нет.

2. **Пункт «Журнал» не совпадает с макетом по назначению.**
   Макет ведёт на `showcase.html` («Журнал»); приложение ведёт на `/activity` («Новости и активность»). `/showcase` существует, но скрыт в другом разделе/футере как «Витрина». Это меняет структуру навигации, а не только URL.

3. **В макете «Ещё» содержит только «Продвижение» и «Редакция»; на приложении туда добавлены Новости/активность, отзывы, альбомы, блоги, о проекте и контакты.**
   Дополнительные пункты могут быть оправданы продуктово, но они не соответствуют составу и порядку макета. По требованию сохранения макета нужно либо перенести их в предусмотренную структуру, либо отдельно утвердить расширение.

4. **Footer не воспроизводит структуру макета.**
   - Макет: блоки «Творчество», «Сообщество», «Автору»;
   - приложение: «Творчество», «Сообщество», «О проекте».
   Выпали/перемещены: «Разделы форума», «Авторская страница», «Редакция»; «Витрина редакции» переименована в «Витрина».

5. **В макете есть блок «Новые пользователи», в `Home.vue` его нет.**
   Это явное структурное расхождение главной: на стенде после восстановления API блок также не появится, так как не реализован в шаблоне.

6. **Ссылки «Смотреть все» для новых комментариев и аналогичные заменены или ведут не к своему разделу.**
   Например, в `Home.vue` «Новые комментарии → Смотреть все» ведёт на `/works`, а не к перечню комментариев; самостоятельного маршрута/интерфейса комментариев нет. В макете эта ссылка обозначена как отдельная функция.

## Функциональная зависимость, требующая проверки на следующей итерации

API на pre-prod **доступен** по точному адресу `POST /api` (без завершающего `/`): проверка `health` вернула `{"status":"ok","ok":true,"database":true}`. В frontend endpoint берётся из `VITE_GRAPHQL_ENDPOINT`; поэтому при следующем деплое нужно проверить, что это значение было задано при build именно как `https://pre-prod.littop.ru/api`.

Без полноценного браузерного прогона пока нельзя честно подтвердить:

- отображение реальных данных во всех блоках;
- переходы каталог → произведение и автор → страница автора на живых сущностях;
- пагинацию/фильтры каталога;
- формы публикаций и форум;
- авторизацию, регистрацию и соцвход.

Важно: ранее проверенные `/graphql`, `/api/graphql` и `/api/health` — неверные пути для данного backend, поэтому их 404/405 не являются проблемой API.
